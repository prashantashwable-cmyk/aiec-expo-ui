## हे डॉक्युमेंट कसं वाचायचं

ही फीचर्सची यादी नाही. हे **वापरण्याचं मॅन्युअल** आहे — स्क्रीनवर काय दिसतं, कोणत्या क्रमाने दिसतं, कोण कशाला हात लावतो, सिस्टीम मागच्या मागे काय करते, आणि काहीतरी चुकलं तर काय होतं — हे सगळं यात आहे.

याची मांडणी पैसा जसा फिरतो तशीच केली आहे:

> **रायडर शाफ्ट शोधतो → बॉट लिफ्ट विकतो → ग्राहक टोकन भरतो → QC शाफ्ट क्लिअर करतो → कंटेनर पाठवला जातो → ग्राहक 90% भरतो → टेक्निशियन बसवतो → QC तपासणी → हॅंडओव्हर → शेवटचे 10% → NOC → AMC**

प्रत्येक रोलच्या प्रकरणात हेच पाच ब्लॉक आहेत, त्यामुळे तुम्ही कुठूनही सुरुवात करू शकता:

| ब्लॉक | यात काय मिळेल |
|---|---|
| **A. कोण आणि त्यांना काय दिसतं** | थीम, भाषा, स्क्रीनची यादी |
| **B. सुरुवातीपासून शेवटपर्यंत** | तासागणिक, टॅपागणिक |
| **C. सेक्शन A चे नियम इथे कसे लागू होतात** | प्रत्येक नियमाचा या रोलशी थेट संबंध |
| **D. या रोलचा पैसा** | नेमकं कशावर आणि किती मिळतं |
| **E. काय अडवतं** | अपयशाचे प्रकार आणि सिस्टीम काय करते |

**चिन्हांचा अर्थ:**
`👤` माणसाची कृती · `🤖` AI/सिस्टीमची कृती · `🔒` कडक अडथळा (पुढे जाताच येत नाही) · `💰` पैशाची घटना · `📍` GPS ने तपासलेलं · `📷` कॅमेऱ्याने तपासलेलं · `⚠️` धोक्याची सूचना

### नियम 1 — प्रत्येक गोष्टीला लोकेशनवर आधारित युनिक ID

या सिस्टीममध्ये ID शिवाय काहीही अस्तित्वात नाही. एकही लीड नाही, एकही बोल्ट नाही, एकही चॅट मेसेज नाही, एकही रुपया नाही.

**रचना:**

```
MH - PUN - KOT - LIFT - 0089 - K
 │     │     │      │      │     │
 │     │     │      │      │     └─ चेक अक्षर (Damm अल्गोरिदम — टायपिंग व तोंडी चुका पकडतं)
 │     │     │      │      └─────── अनुक्रमांक, 4 अंकी, प्रत्येक झोन + प्रकारासाठी वेगळा
 │     │     │      └────────────── घटकाचा प्रकार (4 अक्षरं, खालचा तक्ता पहा)
 │     │     └───────────────────── झोन / भागाचा कोड (3 अक्षरं, GIS वॉर्ड नकाशावरून)
 │     └─────────────────────────── शहराचा कोड (3 अक्षरं)
 └───────────────────────────────── राज्याचा कोड (2 अक्षरं)
```

**घटक प्रकारांचे कोड:**

| कोड | घटक | कधी तयार होतो |
|---|---|---|
| `LEAD` | कच्चं साइट लीड | रायडर Capture दाबतो तेव्हा |
| `CUST` | ग्राहक खातं | टोकन पेमेंट यशस्वी झाल्यावर |
| `LIFT` | प्रत्यक्ष लिफ्ट युनिट | डील जिंकल्यावर |
| `QUOT` | कोटेशनची आवृत्ती | बॉट किंमत तयार करतो तेव्हा |
| `AGMT` | डिजिटल करार | ग्राहक ई-सही करतो तेव्हा |
| `CONT` | स्मार्ट IoT कंटेनर | सप्लायर सील करतो तेव्हा |
| `KITB` | बारकोड लावलेली मटेरियल पिशवी | सप्लायरकडे पॅक होताना |
| `RIDR` | फील्ड रायडर | ऑनबोर्डिंग मंजूर झाल्यावर |
| `TECH` | टेक्निशियन | Level 1 सर्टिफिकेशननंतर |
| `QCIN` | QC इन्स्पेक्टर | Level 5 बढतीनंतर |
| `SUPP` | पुरवठादार | व्हेंडर करार झाल्यावर |
| `PART` | शहर पार्टनर / फ्रँचायझी | रॉयल्टी करार झाल्यावर |
| `PAYT` | कोणतंही पेमेंट | व्यवहार सुरू होताना |
| `WLET` | वॉलेट खातेवही नोंद | कोणतीही जमा/नावे नोंद |

| `SOPX` | SOP स्टेपची नोंद | टेक्निशियन स्टेप उघडतो तेव्हा |

| `AMCX` | AMC करार | NOC दिल्यावर |

**या नियमाचे तीन थरांतले परिणाम:**

1. **पहिला थर — शोध:** अॅपमध्ये कुठेही `KOT-LIFT-0089` टाइप करा, थेट त्या लिफ्टवर पोहोचाल.
2. **दुसरा थर — आपोआप जोडणी:** प्रत्येक फोटो, चॅट, GPS नोंद, रुपया आणि SOP स्टेप तयार होतानाच त्याच्या मूळ ID ला जोडला जातो. **"कामाला जोडा" असं वेगळं पाऊल नाहीच.** तुम्ही कुठे आहात हे अॅपला माहीत आहे, म्हणून तुम्ही कोणतं काम करताय हेही त्याला माहीत आहे.
3. **तिसरा थर — पूर्ण पुनर्रचना:** कोणताही वाद एका ID वरून सोडवता येतो — कोण कुठे उभा होता, कोणत्या मिनिटाला, कोणता फोटो होता, आणि कोणता रुपया कुठे गेला. हीच गोष्ट जबाबदारीचं मॉडेल कोर्टात टिकवते.

**सगळीकडे QR:** प्रत्येक ID चा QR स्टिकर छापला जातो. कंटेनर, मटेरियल पिशव्या, लिफ्टच्या मशीन रूमची प्लेट, टेक्निशियनचं बॅज, ग्राहकाचं वेलकम कार्ड. QR स्कॅन करणं = ती नोंद उघडणं.

### नियम 2 — नकाशा हेच अॅप आहे

या प्रॉडक्टमध्ये कुठेही "आधी यादी" अशी स्क्रीन नाही. प्रत्येक रोल थेट लाइव्ह नकाशावर उघडतो.

- **रायडर**: त्याने टाकलेले पिन + अजून न फिरलेल्या भागांचा हीटमॅप
- **सेल्स**: फनेलच्या टप्प्यानुसार रंग दिलेले लीड पिन
- **ग्राहक**: स्वतःच्या साइटचा पिन + त्याच्याकडे येणारा लाइव्ह कंटेनर
- **टेक्निशियन**: नेमून दिलेल्या साइट्स + रस्ता + आजची SOP स्टेप
- **QC**: तपासणी बाकी असलेल्या साइट्स, अंतरानुसार क्रमाने
- **ॲडमिन**: सगळं, सगळे, लाइव्ह, फिल्टरसह
- **मालक**: महाराष्ट्राचा महसूल-घनतेचा हीटमॅप

याद्या फक्त नकाशावरचं एक *टॉगल* म्हणून आहेत (वरच्या उजव्या कोपऱ्यात `☰ यादी`) — कधीच डीफॉल्ट म्हणून नाही.

**नकाशाची खूण-यादी (सर्व रोलसाठी एकसारखी):**

| रंग | अर्थ |
|---|---|
| ⚪ करडा | नवीन लीड, अजून हात लावलेला नाही |
| 🔵 निळा | सेल्स / वाटाघाटीत |
| 🟣 जांभळा | डील जिंकली, शाफ्ट तयार व्हायची वाट |
| 🟠 केशरी | कंटेनर रस्त्यात |
| 🟡 पिवळा | इन्स्टॉलेशन सुरू |
| 🟢 हिरवा | हॅंडओव्हर पूर्ण, NOC दिलं |
| 🔴 लाल | अडकलेलं / मुदत ओलांडली / अलर्ट |
| ⚫ काळा | गमावलेलं / रद्द |

**कोणताही पिन दाबा → घटक कार्ड वर सरकतं.** सगळीकडे तेच कार्ड: फोटोंची पट्टी, ID, स्थिती, पुढच्या कृतीचं बटण, पैशाची स्थिती, आणि टाइमलाइन.

### नियम 3 — AI हा पर्यवेक्षक आहे, मदतनीस नाही

अॅप कोणी वापरेल याची वाट बघत नाही. ते दिवस चालवतं.

**प्रत्येक रोलला रोजचं वेळापत्रक असतं** — AI मास्टर कंट्रोलर ठरलेल्या वेळी पुढचं काम ढकलतो. पुढे काय करायचं हे वापरकर्ता ठरवत नाही; अॅप सांगतं, आणि घड्याळ स्क्रीनवर दिसत राहतं.

कंट्रोलर सतत पाच गोष्टी करतो:

1. **वाटप** — ठरलेल्या मिनिटाला पुढचं काम, काउंटडाउनसह पाठवतो
2. **पडताळणी** — "झालं" दाबू देण्याआधी GPS, वेळ, फोटोतला मजकूर आणि SOP चा क्रम तपासतो
3. **वाढवत नेणे** — 15 मिनिटांनी आठवण → 30 मिनिटांनी इशारा → 60 मिनिटांनी दुसऱ्याला वाटप → ॲडमिनला अलर्ट
4. **पैसा अडवणे** — पडताळणी नाही, तर वॉलेटमध्ये पैसे नाहीत. यात अपवाद नाही.
5. **शिकणे** — प्रत्यक्ष निकालांवरून रस्ते, लीड स्कोअरिंग आणि वेळेचे अंदाज सुधारत राहतो

**वाढवत नेण्याची शिडी (सर्व रोलसाठी सारखी):**

| टप्पा | कधी | सिस्टीम काय करते |
|---|---|---|
| आठवण | काम 15 मिनिटं उशिरा | पुश नोटिफिकेशन + त्यांच्या भाषेत आवाजी सूचना |
| इशारा | 30 मिनिटं उशिरा | पट्टी पिवळी, वरिष्ठाला कळवलं, स्ट्रीक धोक्यात |
| दंड | 60 मिनिटं उशिरा | स्ट्रीक तुटते, काम खुल्या यादीत जातं |
| पुनर्वाटप | 90 मिनिटं उशिरा | 🤖 5–10 किमी परिसरातल्या पात्र माणसाला सर्ज बोनससह ऑफर |
| फ्लॅग | 30 दिवसांत 3 वेळा पुनर्वाटप | खातं आपोआप निलंबित, ॲडमिनकडे तपासणीला |

### नियम 4 — प्रत्येक कामानंतर लगेच छोटा पैसा (प्रेरणेचं इंजिन)

काम पडताळणीत पास होताच *त्याच क्षणी* वॉलेटमध्ये खरे पैसे जमा होतात. आठवड्याने नाही. प्रोजेक्टच्या शेवटी नाही. **लगेच, आवाजासह आणि अॅनिमेशनसह.**

**यामागचं तीन थरांचं मानसशास्त्र:**

1. **पहिला थर — तात्काळ बक्षीस:** ₹5 ते ₹200 जमा होतात, नाणं पडल्याचं अॅनिमेशन आणि वाढणारा आकडा. कष्ट आणि बक्षीस यातलं अंतर 3 सेकंदांपेक्षा कमी.
2. **दुसरा थर — दिसणारी प्रगती:** प्रत्येक स्क्रीनवर "मनी मीटर" — आजची कमाई, आठवड्याची कमाई, आणि पुढच्या बोनसपर्यंतची पट्टी. अजून ₹500 किती लांब आहेत हे नेहमी दिसतं.
3. **तिसरा थर — गमावण्याची भीती:** स्ट्रीक, लेव्हलची प्रगती आणि झिरो-वेस्टेज बोनस *गमावता* येतात. कमावलेली स्ट्रीक तुटण्याचं दुःख नवी मिळवण्याच्या आनंदापेक्षा मोठं असतं — नवेपणा संपल्यावरही सवय टिकवणारी हीच गोष्ट आहे.

**⚠️ कडक मर्यादा — गेमिफिकेशन बजेट कॅप:**
कोणत्याही कामावरची एकूण छोटी बक्षिसं त्या कामाच्या ग्रॉस मार्जिनच्या ठराविक टक्क्यांपेक्षा जास्त जाऊ शकत नाहीत (शिफारस: **2.5%**, कमाल मर्यादा **4%**). डील जिंकताच अॅप ही मर्यादा मोजतं आणि त्यापुढे रोख देत नाही — उरलेलं रोख नसलेल्या बक्षिसांत बदलतं (बॅज, रँक, आधी काम मिळण्याचा हक्क). **ही मर्यादा नसेल, तर गेमिफिकेशन धंदाच खाऊन टाकेल.**

**वॉलेटचे नियम:**
- छोटी जमा रक्कम आधी **प्रलंबित** स्थितीत येते, QC किंवा AI पडताळणीनंतर **मोकळी** होते
- मोकळी झालेली रक्कम **दर शुक्रवारी** आपोआप बँक खात्यात जाते
- दंड आधी **प्रलंबित** रकमेतून, मग मोकळ्या रकमेतून वजा होतो
- संपूर्ण खातेवही कामगाराला दिसते; प्रत्येक ओळीला `WLET` ID आणि ती रक्कम कमावून देणाऱ्या पुराव्यापर्यंत जाणारी लिंक असते

### नियम 5 — प्रत्येक रोलला नेमकं काम आणि नेमके पैसे माहीत हवेत

कोणतंही काम स्वीकारण्याआधी कामगाराला **टास्क कार्ड** दिसतं — फक्त चार ओळी, बाकी काही नाही:

```
┌────────────────────────────────────────┐
```

### नियम 8 — फ्लोटिंग हेल्प बटण (स्क्रीन ओळखणारं)

**प्रत्येक स्क्रीनवर** खाली उजवीकडे `?` बुडबुडा तरंगत असतो — तो हलवता येतो, आणि तो कधीही मुख्य बटणावर येत नाही.

दाबल्यावर **चार टॅब** उघडतात:

1. **"ही स्क्रीन काय आहे?"** — 3 ओळी, सोप्या भाषेत, चालू भाषेत
2. **"दाखवा"** — *याच* स्क्रीनचा 20–40 सेकंदांचा रेकॉर्ड केलेला व्हिडिओ
3. **"AI ला विचारा"** — वापरकर्त्याचा रोल, चालू स्क्रीन, चालू job ID आणि सध्याचा अडथळा आधीच माहीत असलेला चॅटबॉट. तो परिच्छेद नाही, थेट दाबता येणारी कृती देतो.
4. **"ॲडमिनला फोन"** — एका टॅपमध्ये ड्युटीवरच्या ॲडमिनशी संपर्क; कॉलसोबत चालू स्क्रीन, job ID आणि शेवटची चूक आपोआप जोडली जाते

**तिसऱ्या थराचा तपशील:** प्रत्येक वेळी हेल्प उघडलं की `screen_id` सह नोंद होते. एकाच स्क्रीनवर आठवड्यात 15+ लोकांनी हेल्प उघडलं, तर ॲडमिनला **"गोंधळात टाकणारी स्क्रीन" अलर्ट** जातो — हेल्प बटण हे UI मधल्या चुका शोधणारं यंत्रही आहे.

### नियम 11 — खरा नकाशा, खरा GPS, खरा कॅमेरा — पहिल्या दिवसापासून

प्रत्यक्ष वापरात कुठेही बनावट डेटा नाही. कधीच नाही.

**पहिल्या वापरात परवानग्या मागितल्या जातात, पण OS चा डायलॉग येण्याआधी सोप्या भाषेत कारण सांगणारी स्क्रीन दाखवली जाते:**

| परवानगी | कशासाठी | नाकारल्यास |
|---|---|---|
| लोकेशन (फील्ड रोलसाठी नेहमी) | रस्ता नोंद, जिओफेन्स हजेरी, आपोआप पत्ता | 🔒 फील्ड रोल लीड घेऊ शकत नाहीत, हजेरीही लावू शकत नाहीत |
| कॅमेरा | सर्व पुरावे, QR स्कॅन, हॅंडओव्हर | 🔒 एकही SOP स्टेप पूर्ण होत नाही |

| नोटिफिकेशन | कामाचं वाटप, अलर्ट | रोजचं वेळापत्रक चालवता येत नाही |
| मायक्रोफोन | आवाजी इनपुट, तक्रारीत आवाजी नोंद | मजकुरातून पर्याय |

**खोटेपणा रोखण्याचे उपाय (यावरच संपूर्ण पेमेंट मॉडेल उभं आहे):**

- **खोटं लोकेशन ओळखणं:** प्रत्येक नोंदीत `isFromMockProvider` तपासलं जातं; सापडलं तर खातं लगेच निलंबित
- **फक्त अॅपचा कॅमेरा:** फोटो अॅपच्या कॅमेऱ्यातूनच आले पाहिजेत. गॅलरीतून अपलोड बंद. पुराव्याच्या स्क्रीनवर "गॅलरीतून निवडा" हे बटणच नाही.
- **EXIF + सर्व्हरची वेळ:** फोनची वेळ धरली जात नाही; सर्व्हरवर पोहोचल्याची वेळ नोंदवली जाते
- **जिओफेन्स मर्यादा:** पुरावा साइट पिनपासून 50 मीटरच्या आत काढलेला हवा
- **क्रमाचं कुलूप:** स्टेप 7 पडताळल्याशिवाय स्टेप 8 चा फोटो काढताच येत नाही

- **हॅंडओव्हरला जिवंतपणाची तपासणी:** डिजिटल सहीच्या वेळी समोरच्या कॅमेऱ्याने चेहरा

### नियम 12 — एंटरप्राइझ दर्जा, ॲसेट-लाइट, ॲग्रीगेटर, पूर्ण स्वयंचलित, शून्य जोखीम

व्यवसायाचं तत्त्व, सिस्टीमच्या वर्तनाच्या भाषेत:

- **ॲसेट-लाइट:** कंपनीकडे लिफ्ट नाहीत, माल नाही, गाड्या नाहीत, गोदामं नाहीत. फक्त प्लॅटफॉर्म आणि ग्राहकाशी नातं. पैसे मिळेपर्यंत माल सप्लायरचाच; मजूर नोकरीवर नाहीत, जोडलेले आहेत.
- **ॲग्रीगेटर:** सप्लायर आणि टेक्निशियन स्वतंत्र भागीदार म्हणून जोडले जातात, कामगिरीनुसार रेटिंग आणि वाटप. क्षमता वाढवायची तर पगारपट नाही, भागीदार वाढवा.
- **स्वयंचलित:** 95%+ टप्पे माणसाच्या हस्तक्षेपाशिवाय पार पडावेत हे लक्ष्य. माणूस नेमका तीनच ठिकाणी लागतो: 30% खालची वाटाघाट, पुराव्यावरचा वाद, आणि सुरक्षिततेचा प्रसंग.
- **एका माणसाची देखरेख:** ॲडमिन कन्सोल फक्त अपवाद हाताळण्यासाठी बनवलं आहे. ॲडमिन रोजचं काम करत असेल, तर स्वयंचलन फसलंय — आणि System Efficiency Index ते दाखवेल.
- **उत्पादन रेषा:** प्रत्येक काम ठरलेल्या स्टेशनांमधून जातं, प्रत्येक स्टेशनला प्रवेश आणि निर्गमनाचं गेट आहे. एकही काम स्टेशन वगळू शकत नाही.
- **जोखीम कमी (हे नीट वाचा):** टप्प्याटप्प्याने पेमेंट, डिजिटल करार, GPS-तपासलेले हॅंडओव्हर, तीन किल्ल्यांचं कुलूप आणि पुराव्यावर अडवलेली मजुरी — यामुळे **आर्थिक आणि वादाची** जोखीम जवळपास शून्य होते.

60% ची जागा यासाठी आहे की ग्राहकाला **आपण जिंकलो** असं वाटावं — या बाजारात डील तसंच होतं. पण भाव अवास्तव फुगवला, तर ज्याच्याकडे आधीच तीन कोटेशन आहेत असा माहितगार ग्राहक विश्वास गमावतो. म्हणून सिस्टीम **market-sanity check** करते: त्याच configuration साठी त्या झोनमधल्या स्पर्धकांच्या 90व्या टक्केवारीपेक्षा यादी भाव जास्त झाला, तर engine सुरुवातीचं markup आपोआप कमी करतं. **खोट्या भावावरची खोटी सवलत फक्त एकदाच चालते.**

कोटेशन PDF मध्ये: तपशीलवार स्पेसिफिकेशन, रायडरच्या फोटोंवरून बनवलेलं 3D शाफ्ट रेंडरिंग, डिलिव्हरीचं वेळापत्रक, पेमेंटचे टप्पे (10k / 90% / 10%), EMI पर्याय, वॉरंटी आणि AMC अटी — आणि स्वतःचा आयडी `MH-PUN-KOT-QUOT-0447-01-R`. प्रत्येक बदलाची आवृत्ती वाढते आणि जुनी जपली जाते.

### **T+11 मिनिटं — 🤖 निगोशिएशन बॉट**

WhatsApp वर, ग्राहकाच्या भाषेत, कडक नियमांसह:

| नियम | वागणूक |
|---|---|
| सवलतीने सुरुवात कधीच नाही | आधी मूल्य: वॉरंटी, 2 आठवड्यांची हमी, IoT-सुरक्षित माल |

### **T+2 दिवस — 👤 Manual Desk (गरज असेल तरच)**

**S4** वर आलेल्या डीलसोबत सगळं आधीच तयार असतं: पूर्ण संभाषण, सर्व कोटेशन आवृत्त्या, ग्राहकाचा नेमका आक्षेप, मार्जिनची स्थिती, आणि 🤖 **सुचवलेला counter-offer + जिंकण्याची शक्यता किती टक्के.** माणूस 20% ते 30% मार्जिनमध्ये बोलणी करतो. 20% खाली फक्त मालकाची मंजुरी, लेखी कारणासह, कायमची नोंद.

### **T+3 दिवस — 👤 डील झाली → डिजिटल करार**

```
🤖 करार आपोआप तयार (Aadhaar eSign / DSC नुसार)
   ↓
ग्राहकाला WhatsApp + अ‍ॅप लिंक
   ↓
👤 वाचतो (तिन्ही भाषा, शेजारी शेजारी बघता येतात)
   ↓

   ↓
🤖 AGMT आयडी तयार, PDF लॉक, hash साठवला, दोघांना प्रती
   ↓
💰 ₹10,000 टोकनची पेमेंट स्क्रीन त्याच प्रवाहात लगेच उघडते
```

**₹10,000 का, आणि सहीच्या त्याच श्वासात का (स्तर 3):**
8 लाखांच्या खरेदीवर ₹10k म्हणजे 1.3% पेक्षा कमी — इतकं कमी की बिल्डर मीटिंग न घेता भरतो. **हाच मुद्दा आहे: ही कमाई नाही, ही बांधिलकी आहे.** पैसा हलल्या क्षणी डीलचं मानसशास्त्र "आम्ही विक्रेते बघतोय" वरून "आमचा लिफ्ट प्रोजेक्ट सुरू झाला" असं बदलतं. ग्राहक स्क्रीन सोडण्याआधी, **सहीच्याच प्रवाहात** पैसे मागितल्याने वसुली जवळपास दुप्पट होते — नंतर लिंक पाठवण्यापेक्षा.

### **T+3 दिवस, +2 मिनिटं — 🤖 साखळी सुरू होते**

टोकन आल्यावर आठ गोष्टी माणसाशिवाय घडतात:

1. `CUST` आयडी तयार, ग्राहक खातं सुरू, Premium थीम
2. `LIFT` आयडी तयार — प्रत्यक्ष युनिट आता सिस्टीममध्ये आहे
3. नकाशावरचा पिन 🟣 जांभळा होतो
4. **शाफ्ट तयारीचं SOP** ग्राहकाला पाठवलं जातं (भाग 4)
5. शाफ्ट तयार + 1 दिवस अशी QC तपासणी आपोआप ठरते
6. सप्लायरला कळवलं, माल तात्पुरता राखून ठेवला
7. 💰 रायडर रवीला ₹1,500 कमिशन — त्याने घेतलेल्या साइटचं नाव सांगणाऱ्या नोटिफिकेशनसह

महसूल वाढत असताना SEI घसरत असेल, तर कंपनी हळूहळू **माणसांवर चालणारी** होत आहे — आणि asset-light मॉडेल नेमकं तेच टाळण्यासाठी आहे. **महसुलाआधी हा आकडा बघा.**

### **पॅनेल 4 — धोरणात्मक अलर्ट आणि विस्तार**

आठवड्याने, रोज नाही. **दिवस बदलणाऱ्या नाही, निर्णय बदलणाऱ्या गोष्टी:**

## 11.2 हे मॉडेल चालवणाऱ्या तीन गोष्टी

1. **कंपनी मालात एकही रुपया गुंतवत नाही.** सप्लायरला ग्राहकाच्याच 90% मधून पैसे जातात. प्रत्येक डीलसाठी लागणारं खेळतं भांडवल ≈ ₹0.

## 11.3 Gamification बजेटची तपासणी

या डीलवरची एकूण micro-reward रक्कम: रायडर (₹40 + ₹1,500 + ₹1,000) + टेक्निशियन बोनस (₹7,500) + QC बोनस (₹150) ≈ **₹10,190**, आणि contribution margin ₹1,42,710 = **7.1%**.

> ⚠️ **ही नियम 4 च्या सुचवलेल्या 2.5% च्या वर आणि 4% च्या मर्यादेजवळ आहे** — कारण यात conversion कमिशन आणि पूर्णत्वाचे बोनसही मोजले आहेत.
>
> **बरोबर पद्धत:** conversion कमिशन आणि पूर्णत्वाचे बोनस हे **विक्रीचा थेट खर्च** म्हणून वेगळे धरा (ते तसेच आहेत), आणि फक्त **ऐच्छिक gamification** — streak, leaderboard, target बोनस, wastage बोनस — यावर 2.5% ची मर्यादा लावा.
>
> **हे वर्गीकरण पहिल्या दिवसापासून खातावहीत बरोबर करा**, नाहीतर gamification चा खर्च auditor ला आणि पुढे गुंतवणूकदाराला अनियंत्रित वाटेल.

## शेवटची नोंद

हे डॉक्युमेंट अशा धंद्याचं वर्णन करतं जिथे **सिस्टीमच व्यवस्थापक आहे.** सेक्शन A मधला प्रत्येक नियम माणसाचा एक निर्णय काढून टाकण्यासाठी आहे, आणि सेक्शन B मधला प्रत्येक मुद्दा production line वरचं एक स्टेशन आहे — आत जाण्याचं गेट आणि बाहेर पडण्याचं गेट असलेलं.

**हे प्रत्यक्षात चालेल की नाही, हे तीन गोष्टी ठरवतील:**

1. **पुराव्याची सिस्टीम दोन्ही बाजूंनी विश्वासार्ह असली पाहिजे** — फसवणुकीवर कडक, आणि प्रामाणिक कामगारावर न्याय्य. **चुकून रोखलेला एक पगार कोणत्याही भरती मोहिमेपेक्षा वेगाने टेक्निशियनच्या वर्तुळात पसरतो.**

2. **Compliance चा पाया अ‍ॅपच्या आधी बांधला पाहिजे, नंतर नाही.** भाग 14 हे कागदी काम नाही. **ती भार पेलणारी भिंत आहे.**

3. **गेट कधीच सैल करू नयेत.** एका ग्राहकाला पैसे न घेता NOC दिलं, किंवा एका टेक्निशियनला पुराव्याशिवाय पैसे दिले — त्या क्षणी **सिस्टीममधलं प्रत्येक गेट वाटाघाटीयोग्य होतं**, आणि हे मॉडेल पुन्हा एक पारंपरिक लिफ्ट धंदा बनतं, फक्त सुंदर स्क्रीन असलेला.
